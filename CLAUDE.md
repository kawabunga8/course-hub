## Architecture

**Course Hub** is a Next.js 16 App Router app that serves as the central student data source for a suite of RCS (Richmond Christian School) tools: TOC-Dayplans, RCS Report Card Tool, Kawahoot, and Group Maker. It writes to a shared Supabase database; the other apps read from it, directly or through Course Hub's API (`src/app/api/*`). Course Hub is the only app that writes the tables below. Who actually writes what, measured from code, is in `ARCHITECTURE.md` §5.

### Supabase tables (owned here; Course Hub is the only app that writes them)
- `public.students` — core student records (name, grade, gender, photo_url, student_number, email)
- `public.enrollments` — student ↔ course, per school year, with the student's `grade_year` that year. `course_id` is authoritative.
- `public.courses` — one row per course per school year (block, room, quarters, sort order), linked to `course_catalog` by `course_code` and grouped by `teaching_group_id`
- `public.teaching_groups` — which courses are taught together in one room at one time (e.g. Band 10/11/12). No screen yet: SQL only.
- `public.course_catalog` — a course's stable identity across years (`code`, `status` active/dormant/retired). No screen yet.
- `public.school_years` — canonical year list, `is_current`, `is_archived`, records-coverage dates. No screen yet.
- `public.school_quarters` — quarter dates per school year
- `public.student_notes` — per-student timestamped notes
- `public.student_marks` — per-student subject marks with quarter and class references
- `public.learning_standards`, `public.learning_standard_rubrics` — versioned curriculum standards and rubrics (`/standards`)
- `public.school_documents` — school-wide reference documents (`/documents`)

### Generated by the database (never write these from any app)
- `public.classes` — one row per teaching group, rebuilt by triggers when a course or teaching group changes. A guard trigger rejects direct edits to its name, block, quarters, year or group. TOC Day Plans hangs day plans off it, and may write only its own `toc_template_id` and `grade_level` columns.
- `public.enrollments.class_id` — filled from `course_id` by a trigger
- `rcs.enrollments` rows for courses linked in `rcs.course_hub_links` — copied from `public.enrollments` by a trigger

Photos are stored in the Supabase Storage bucket **"Student Photos"**.

### AI & student data (if adding an AI feature here)
Course Hub doesn't call any AI provider today, but it owns sensitive per-student tables (`student_notes`, `student_marks`). Standing RCS rule: Claude is fine for features with no student data in the prompt; anything that would send individual student records/notes to an AI must use a locally-run model instead (see rcs-report-card-tool's `CLAUDE.md` "AI Generation"/"AI Roadmap" sections for the established pattern — env-var-gated Ollama fallback, dynamic model field, explicit `num_ctx`).

### Supabase client pattern
- **Browser (client components):** use `getSupabaseClient()` from `src/lib/supabaseClient.ts` — singleton `createBrowserClient` instance, throws if called server-side.
- **Middleware:** `createServerClient` from `@supabase/ssr` using `req.cookies`.
- **Server (API routes only):** `createAdminClient()` from `src/lib/supabase/admin.ts`, after `requireApiKey` from `src/lib/require-api-key.ts`. Pages still fetch client-side.

### Auth flow
`src/middleware.ts` guards all routes except `/login`, `/auth/callback`, and `/api/*`. Unauthenticated requests redirect to `/login?next=<path>`. After sign-in or password reset, `/auth/callback/page.tsx` handles the `onAuthStateChange` event and redirects accordingly.

### Page structure
Each route uses a thin Server Component page that wraps a `*Client.tsx` component in `<Suspense>`. All business logic and data fetching lives in the client components.

- `/` — redirects to `/students` (root page)
- `/login` — email/password sign-in + forgot password (sends reset email to `/auth/callback`)
- `/students` — main app: student list, search/filter, detail panel with tabs (Info, Classes, Notes, Marks), CSV import, photo upload
- `/students/photos` — bulk photo upload
- `/courses` — courses per school year; `/courses/attendance` — printable attendance sheet
- `/quarters` — quarter dates; `/standards` — learning standards; `/documents` — school reference documents
- `/api/*` — API-key protected. GET routes are the read API for the other apps (courses, rosters, students, quarters, attendance); `POST /api/admin/standards/import` is Course Hub's own standards import
